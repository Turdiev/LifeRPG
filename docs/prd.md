# LIFE RPG — PRD (MVP)

Nov 4, 2026 · @Ярик

## Обзор продукта

LIFE RPG — ежедневник в виде PWA, который превращает большую цель в иерархию квестов по образцу RPG, чтобы всегда было понятно, какой следующий шаг сделать.

**Проблема.** Большие цели парализуют: непонятно, с чего начать, прогресс не виден, мотивация падает. Обычные to-do-списки плоские и не показывают, как сегодняшняя задача связана с большой целью. Геймифицированные трекеры вроде Habitica работают с привычками, а не с разбиением целей.

**Решение.** Цель — это сюжетная линия, которая делится на главы, задания и этапы. Каждый уровень показывает свой прогресс, а один «активный квест» всегда закреплён наверху, как маркер на карте в игре.

**Целевой пользователь MVP.** Автор и 5–10 друзей-тестеров. Это люди с 1–3 личными целями на горизонте от месяца до года (учёба, спорт, личные проекты), которые пользуются смартфоном каждый день и знакомы с играми.

**Цели MVP**

1. Проверить гипотезу: иерархия квестов и активный квест помогают регулярно двигаться к цели.
2. Получить устойчивую основу для следующих версий: ИИ-разбиение, пати, награды.
3. Учебная цель автора: React, бэкенд, затем AI-инжиниринг.

**Метрики успеха**

| Метрика | Как считаем | Цель MVP |
| --- | --- | --- |
| Удержание D7 | Доля тестеров, открывших приложение на 7-й день после первого входа | ≥ 60% |
| Удержание D30 | То же на 30-й день | ≥ 40% |
| Выполненные этапы | Среднее число закрытых этапов и заданий в неделю на активного пользователя | ≥ 5 |
| Живые цели | Доля пользователей хотя бы с одной сюжетной линией в работе | ≥ 80% |
| Использование автором | Дней в неделю, когда автор открывает приложение, в течение первого месяца | ≥ 5 |

Целевые значения — стартовые ориентиры; пересматриваем их после первых двух недель с тестерами. Аналитика событий вынесена за MVP, поэтому до неё метрики считаем приблизительно: по датам выполнения квестов и сессиям входа в базе, плюс разговоры с тестерами.

## Ключевые понятия

Всё в приложении — это квесты четырёх уровней, вложенные друг в друга; глубина фиксирована, чтобы интерфейс и логика оставались простыми.

| Уровень | Игровая аналогия | Что содержит | Пример |
| --- | --- | --- | --- |
| Сюжетная линия | Основной квест | Главы или сразу задания | Пробежать полумарафон к маю |
| Глава | Акт сюжета | Задания | Глава 1. Набрать базу |
| Задание | Квест в журнале | Этапы (необязательно) | Бегать 3 раза в неделю весь январь |
| Этап | Цель квеста | Ничего, это лист дерева | Пробежка 5 км в понедельник |

Правила структуры:

- Главы необязательны: для небольшой цели задания кладутся прямо в сюжетную линию.
- Этапы необязательны: задание без этапов отмечается выполненным целиком.
- Любой элемент имеет название (до 120 символов), а также может иметь описание и дедлайн.

**Активный квест** — одно задание, которое пользователь сейчас «отслеживает». Оно закреплено наверху главного экрана вместе со следующим невыполненным этапом, как маркер на карте в игре.

**Журнал квестов** — экран со списком всех сюжетных линий и их прогрессом.

**Прогресс** — доля выполненного на каждом уровне; он всегда вычисляется из потомков и не вводится вручную.

## Пользовательские сценарии

Главный сценарий MVP — ежедневный: открыть приложение, увидеть активный квест, закрыть следующий этап и увидеть, как растёт прогресс цели.

1. **Первый вход.** Пользователь нажимает «Войти через Google» и видит пустой журнал с одной подсказкой: «Создай первую сюжетную линию». Вводит название цели, по желанию описание и дедлайн.
2. **Разбиение цели.** Внутри сюжетной линии добавляет главы, в главы — задания, в задания — этапы. Enter после ввода создаёт следующий элемент того же уровня, чтобы список набирался быстро.
3. **Выбор активного квеста.** Пользователь отмечает задание как активное. Оно закрепляется наверху главного экрана вместе со своим следующим этапом.
4. **Ежедневная работа.** Пользователь открывает приложение, отмечает этап выполненным одним касанием и видит обновлённый прогресс задания, главы и цели. Когда задание закрыто, приложение предлагает следующее.
5. **Пауза.** Цель или глава ставится на паузу без потери прогресса: её задания не предлагаются как следующие, пока пользователь её не возобновит.
6. **Перестройка плана.** Пользователь переименовывает элементы, меняет порядок, отменяет ненужную ветку или удаляет её с подтверждением.
7. **Обзор целей.** В журнале квестов пользователь смотрит все сюжетные линии с фильтрами «В работе», «На паузе», «Завершённые», «Отменённые».
8. **Завершение цели.** Когда закрыт последний элемент, показывается экран завершения, а сюжетная линия уходит в «Завершённые».
9. **Два устройства.** Пользователь планирует цель на компьютере, а отмечает этапы с телефона; данные одни и те же.

## Бизнес-логика

Вручную пользователь отмечает только листья, паузу и отмену; выполнение контейнеров и прогресс всегда вычисляются снизу вверх.

### Статусы

| Статус | У каких уровней | Как появляется |
| --- | --- | --- |
| Открыто | Все | По умолчанию при создании |
| Выполнено | Все | Лист — касанием; задание с этапами, глава и линия — автоматически, когда выполнены все их неотменённые потомки |
| На паузе | Сюжетная линия, глава | Вручную |
| Отменено | Все | Вручную; при восстановлении возвращается в прежнее состояние по своим детям |

Все переходы обратимы. Снятая отметка возвращает элемент в «Открыто» вместе с выполненными потомками. После возобновления и восстановления элемент возвращается в состояние по своим детям: «Выполнено», если выполнены все его неотменённые потомки, иначе «Открыто»; отменённый этап возвращается открытым.

### Прогресс

- Лист — это этап или задание без этапов; отменённые этапы не в счёт.
- Прогресс элемента = выполненные листья внутри него ÷ все неотменённые листья внутри него. Пример: в главе 3 задания по 4 этапа, выполнено 6 этапов → 50%.
- Пустой контейнер показывает 0% и может быть отмечен выполненным вручную.
- Прогресс не хранится в базе, а вычисляется при чтении, поэтому не может рассинхронизироваться.

### Каскадные правила

1. Выполнение листа пересчитывает прогресс всех предков. Если у родителя выполнены все неотменённые дети, он становится «Выполнено», и проверка идёт выше.
2. Снятие отметки или добавление нового элемента в выполненный контейнер возвращает его и выполненных предков в «Открыто».
3. Ручная отметка задания с открытыми этапами показывает вопрос «Отметить все этапы выполненными?». При согласии закрываются все этапы.
4. Пауза линии или главы не меняет статусы потомков, но их задания не предлагаются и не могут быть активными. Возобновление возвращает всё как было.
5. Отмена убирает ветку из прогресса родителя, не удаляя её; восстановление возвращает ветку обратно.
6. Удаление стирает элемент и всех потомков после подтверждения; восстановить их нельзя.

### Активный квест

- У пользователя не больше одного активного задания. Это отдельная ссылка в профиле пользователя, а не статус задания.
- Активным может быть только открытое задание, у которого ни один предок не на паузе и не отменён.
- Главный экран показывает название задания, путь «Линия › Глава», прогресс и первый открытый этап по порядку.
- Когда активное задание выполнено, отменено или его ветка на паузе, отметка снимается. Приложение предлагает следующее открытое задание: сначала в той же главе, затем в следующей главе той же линии.

### Порядок и дедлайны

- Внутри родителя элементы упорядочены вручную; новые добавляются в конец.
- «Следующий» элемент — первый открытый по порядку.
- Дедлайн информационный: просроченный элемент подсвечивается, но ничего не теряется и не штрафуется.

## Нефункциональные требования

Приложение должно ощущаться мгновенным на телефоне и не терять данные; масштаб MVP — до 50 пользователей.

| Область | Требование |
| --- | --- |
| Скорость | Главный экран открывается быстрее 2 секунд на телефоне среднего уровня через 4G; отметка этапа отображается сразу (оптимистичное обновление) |
| Объём | До 50 пользователей и до 2 000 элементов на пользователя без заметных задержек |
| Устройства | Актуальные Chrome, Safari на iOS, Firefox; ширина экрана от 360 px |
| PWA | Устанавливается на главный экран, открывается без адресной строки |
| Надёжность | Ежедневная резервная копия базы; ни одно действие пользователя не теряется при обрыве сети |
| Безопасность | Только HTTPS; данные изолированы по пользователю на уровне API и базы; из персональных данных хранятся только email, имя и аватар из Google-аккаунта |
| Доступность | Контраст текста по WCAG AA, зоны касания не меньше 44 × 44 px, управление с клавиатуры на компьютере |
| Интерфейс | Русский язык; все тексты в отдельных файлах для будущих переводов; светлая и тёмная тема по настройке системы |

При выходе за круг друзей понадобятся политика конфиденциальности, экспорт и удаление аккаунта по требованиям GDPR.

## Не входит в MVP

Всё ниже сознательно отложено: сначала проверяем, что сама механика квестов работает без игрового слоя и ИИ.

| Функция | Зачем она нужна | Версия |
| --- | --- | --- |
| ИИ-разбиение цели на квесты | Убирает главное трение — ручное планирование | v2 |
| Опыт, уровни, навыки по сферам жизни | Долгосрочная мотивация и видимый рост | v2 |
| Собственные награды пользователя | Связь прогресса с реальными радостями | v2 |
| Повторяемые квесты-«контракты» | Привычки внутри целей | v2 |
| Напоминания и уведомления | Возвращать пользователя каждый день | v2 |
| Ретроспектива по завершении главы | Учиться на своём опыте | v2 |
| Аналитика событий и точные метрики удержания | Цифры для метрик успеха без ручного подсчёта | v2 |
| Зависимости и разблокировка, карта квестов | Ощущение пути и открытия нового | v3 |
| ИИ-помощник с инструментами | Перепланирование словами: «перенеси спорт на неделю» | v3 |
| Пати и совместные квесты | Взаимная ответственность с друзьями | v3 |
| Нарративные описания и летопись героя | Атмосфера и история достижений | v3 |
| Нативные приложения, монетизация | Только если продукт выйдет за круг друзей | Позже |

Просьбы тестеров записываются в бэклог и попадают в MVP, только если блокируют главный сценарий.
